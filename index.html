04 / THE SYNCHRONIZATION DEPENDENCY

省的是“等待依赖”，不只是拷贝几个整数Remove a dependency, not just a few integer copies

优化关：等精确长度OFF: wait for exact lengths

CPU准备attention参数 → 等NPU完成长度更新 → 读回有效KV长度 → 继续下发草稿。CPU prepares attention metadata → waits for NPU length updates → reads valid KV lengths back → dispatches draft work.

优化开：上界先行、设备保真ON: use a bound; device enforces validity

CPU已有可信长度上界 → 不等这次读回 → 设备按真实长度遮住无效尾部。配套包含gather、mask和FIA布局变化。A trusted CPU upper bound avoids this readback; device-side true lengths mask invalid tails. The path also includes gather, masking and FIA layout changes.

概念示例（非实测）：CPU知道有效KV最多12个，NPU知道真实只有9个；传入上界12不等于接受12个token，设备必须遮住位置9–11。KV有效长度和DSpark接受长度是不同计数。Illustration, not a measurement: CPU knows at most 12 KV positions are valid; NPU knows the true count is 9. Passing 12 does not mean accepting 12 tokens: positions 9–11 must be masked. Valid KV length and DSpark acceptance length are distinct counts.
